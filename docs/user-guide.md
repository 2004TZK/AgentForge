# AgentForge 用户使用指南

> 适用版本：v1.x（决策 v1.4：千问云端 API，无本地模型）
> 本文面向第一次使用 AgentForge 的用户，用最直白的方式说明"怎么把它跑起来、怎么用起来"。

---

## 1. 这个项目是干什么的

AgentForge 是一个 **AI 助手（智能体）搭建平台**。你不需要懂 AI 原理，只要在网页上配置几下，就能造出一个"有性格、有知识、会干活"的 AI 助手，然后和它聊天。

它的四大核心能力：

| 能力 | 大白话解释 |
|---|---|
| 知识库（RAG） | 上传资料后，AI 回答问题时只依据你的资料，不瞎编 |
| 工具调用 | AI 能自己调用计算器、GitHub 查询等工具，算数、查项目 |
| 记忆 | 记住和你的聊天上下文，对话更连贯（M3 接入） |
| 工作流 | 把多步操作串成流水线自动执行（M3 实现） |

能造的方向示例：AI 编程助手、AI 客服助手、AI 知识库助手、AI 研究助手、AI 数据分析助手。

---

## 2. 启动前准备

1. 电脑安装并启动 **Docker Desktop**（Windows）
2. 准备一个现代浏览器（Chrome / Edge 均可）
3. 准备一个千问云端 API Key（platform.qianwenai.com 申请，`sk-` 开头），填入项目根目录 `.env` 的 `LLM_API_KEY`（`.env` 由 `cp .env.example .env` 生成）

> 项目模型层使用千问云端 API（对话 qwen3.7-plus + 向量 text-embedding-v3，OpenAI 兼容），**无需本地 GPU、无需下载模型**，只需联网与一个 API Key。

---

## 3. 启动项目

在项目根目录（`AgentForge`）打开终端，执行：

```bash
docker compose up -d --build
```

启动完成后：

- 打开浏览器访问：**http://localhost**
- 后端 API 文档：http://localhost/api/swagger-ui
- 健康检查：http://localhost/api/actuator/health

常用命令：

```bash
docker compose ps          # 查看 9 个服务状态
docker compose logs -f ai  # 查看 AI 服务日志
docker compose stop        # 停止（数据保留）
docker compose up -d       # 再次启动
```

> 首次进入页面如果提示连接失败，确认 Docker 已就绪、`.env` 中 `LLM_API_KEY` 已正确填写后刷新页面即可。

---

## 4. 注册与登录

- 打开 http://localhost，点击"注册"创建账号，或直接使用本地演示账号：**admin / admin123**
- 登录后左侧导航有三个页面：**智能体 / 聊天 / 文件**
- 右上角显示当前用户名，可退出登录

> 目前没有"找回密码"功能，忘记密码需联系管理员在数据库中重置，或重新注册新账号。

---

## 5. 创建你的第一个智能体

**第一步：进入"智能体" → 点击"新建智能体"。**

表单字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| 名称 | ✅ | 助手的名字，如"Java 专家" |
| 描述 | — | 一句话介绍它是干什么的，方便列表里识别 |
| 系统提示词 | ✅ | **最关键**。定义它的角色与行为，见下方模板 |
| 模型 | — | 当前由后端环境统一决定（`qwen3.7-plus` 云端），一般保持默认即可 |
| 温度（0-1） | — | 数值越低回答越严谨保守，越高越有创意发散；默认 0.7 |
| 工具配置 | — | 给助手装配工具，见第 7 节 |

系统提示词示例：

```text
你是一名资深 Java 工程师，擅长 Spring Boot 与微服务架构。
回答要求：
1. 用中文回答，语言简洁；
2. 涉及代码时给出完整可运行的示例；
3. 不确定的地方要如实说明，不要编造。
```

**第二步：填写后点击"保存"**，页面会跳转到编辑页；再次进入"智能体"列表即可看到它。

列表页支持对智能体进行 **编辑 / 删除**。

## 6. 给智能体装知识库（可选）

想让 AI "读过你的资料再回答"，进入 **"文件"** 页面：

1. 顶部选择目标智能体
2. 点击上传，选择文件（支持 **pdf / docx / txt / md**，单个文件 **≤ 20MB**）
3. 上传后自动入库，状态流转：**等待处理 → 处理中 → 已入库**

状态说明：

| 状态 | 含义 | 可以做什么 |
|---|---|---|
| 等待处理 / 处理中 | 正在解析入库 | 等待，页面每 3 秒自动刷新 |
| 已入库 | 知识已可用 | 去聊天页提问 |
| 处理失败 | 解析出错 | 点击"重试"重新入库 |

注意事项：

- 知识库**按智能体隔离**：给 A 智能体传的文件，B 智能体看不到
- **删除文档 = 同时删除磁盘文件与知识库向量**，删除前请确认
- PDF 会按页解析并保留页码，回答引用时可以定位到具体页
- 建议：资料内容越聚焦，回答越准确；一次不要传太多杂乱的文档

---

## 7. 给智能体装工具（可选）

在"编辑智能体"页的**工具配置**中，添加并启用工具：

| 工具 | 用途 | 触发示例 |
|---|---|---|
| calculator | 数学计算（安全求值） | 问"计算 (128+64)÷8" |
| github | 分析 GitHub 项目，返回项目名 / Star 数 / 语言 / 简介 | 问"分析 github.com/spring-projects/spring-boot" |

当前工具按规则触发（M3 后将升级为 AI 自主判断是否调用）。触发规则：

- 消息整体是一个数学算式 → 调用 calculator
- 消息包含 `github: 仓库路径` 或 `github/用户名/仓库名` → 调用 github

---

## 8. 开始聊天

进入 **"聊天"** 页面：

1. 左侧选择智能体
2. 点击 **＋新建** 创建会话
3. 在输入框提问，回车发送

使用体验说明：

- **流式输出**：回答以打字机效果逐字呈现，无需等待全部生成
- **来源引用**：基于知识库回答时，答案下方会列出引用文件，**点击可查看具体片段**
- **多会话**：一个智能体可以开多个会话（如"面试准备""项目答疑"），各自独立互不混淆
- **删除会话**：删除后该会话消息不再展示（底层数据保留）
- **失败重试**：网络异常时发送会失败并提示，可再次发送

提问示例：

| 场景 | 提问 |
|---|---|
| 普通问答 | "HashMap 和 Hashtable 有什么区别？" |
| 知识库问答 | "根据我上传的资料，Spring Bean 生命周期是怎样的？" |
| 工具调用 | "计算 (128+64)÷8" / "分析一下 github.com/spring-projects/spring-boot" |

## 9. 常见问题（FAQ）

**Q：回答很慢？**
A：当前为千问云端 API，正常首字响应在数秒内；若明显变慢，先检查网络，或改 `.env` 的 `LLM_MODEL` 换更快的模型（如 `qwen3.7-flash`）。

**Q：回答偶尔不准确？**
A：可尝试改 `.env` 的 `LLM_MODEL` 升级到更大的模型（如 `qwen3.7-max`）；知识库场景请确保文件已入库、提问带上主题词。

**Q：上传了文件，但 AI 回答没用上资料？**
A：先确认文件状态是"已入库"；提问时把问题说清楚，尽量带上文档主题词；知识库检索不到时会自动降级为普通对话。

**Q：智能体里的"模型"字段填了没反应？**
A：Agent 未绑定自定义 Provider 时使用后端环境变量配置的模型（`qwen3.7-plus`）；如需按智能体指定模型，可在"模型"页新建云端 Provider（OpenAI 兼容）并绑定到智能体。

**Q：http://localhost 打不开？**
A：确认 Docker Desktop 已启动、`docker compose ps` 中服务均为 Up。

## 10. 术语表（新手友好）

| 术语 | 大白话解释 |
|---|---|
| Agent / 智能体 | 你配置出来的那个"AI 助手" |
| 系统提示词 | 给 AI 定的人设和行为规则，它每次回答都会遵守 |
| 温度 | 控制回答随机性：低=严谨，高=有创意 |
| RAG / 知识库 | 让 AI 先检索你的资料再回答，减少瞎编 |
| Embedding | 把文字变成"语义坐标"，让 AI 能比较"意思相近"的内容 |
| 会话 | 一段连续的对话记录；不同会话互相独立 |
| Qdrant | 存知识库向量的数据库 |
| SSE / 流式 | 回答逐字输出，不用干等 |
