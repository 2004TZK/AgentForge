## 2. Spring Boot Maven 模块设计

### 2.1 设计原则

- 以「业务域」划分模块，便于后续服务拆分（用户/Agent/对话/文件可独立演进）。
- 依赖单向：业务模块 → framework → common，禁止反向依赖和循环依赖。
- 模块内统一分层：`controller → service → mapper`，DTO/VO 与 Entity 分离。

### 2.2 模块清单

| 模块 | 职责 | 主要依赖 |
|---|---|---|
| agentforge-common | 统一返回 `Result<T>`、错误码、业务异常、常量、工具类 | 仅第三方工具库 |
| agentforge-framework | Spring Security 配置、JWT 过滤器、Redis 配置、全局异常处理、CORS、Web MVC 配置 | common、security、data-redis、jjwt |
| agentforge-system | 用户注册/登录/信息、JWT 签发、认证服务 | common、framework |
| agentforge-module-agent | Agent CRUD、Agent-Tool 配置、文档元数据 | common、framework、MyBatis Plus |
| agentforge-module-conversation | 聊天记录保存与历史查询 | common、framework、MyBatis Plus |
| agentforge-module-file | 文件上传、落盘、状态管理、RAG 任务编排 | common、framework、ai-gateway |
| agentforge-module-ai-gateway | 封装 Python AI Service HTTP 客户端、内部鉴权、后续 SSE 流式 | common、framework |
| agentforge-start | 启动类、application.yml、运行入口 | 依赖全部业务模块 |

### 2.3 模块依赖关系

```text
                    agentforge-start
          /       /        |        \        \
   system    agent   conversation    file   ai-gateway
          \       \        |        /       /
                 agentforge-framework
                        |
                 agentforge-common
```

### 2.4 关键依赖版本基线（编码前锁定小版本）

| 组件 | 版本 | 说明 |
|---|---|---|
| Java | 21 | 项目要求 |
| Spring Boot | 3.3.x（3.x 稳定线） | 项目要求 |
| Spring Security | 6.x | 随 Spring Boot 管理 |
| MyBatis Plus | 3.5.x | 使用 `mybatis-plus-spring-boot3-starter` |
| MySQL Connector/J | 8.3+ | 随 Spring Boot 管理 |
| jjwt | 0.12.x | JWT 生成与校验 |
| springdoc-openapi | 2.x | API 文档（/swagger-ui） |
| spring-boot-starter-actuator | 随 Boot | 健康检查 |
| Lombok | 最新稳定 | 减少样板代码 |

### 2.5 模块内分层约定

- `entity`：与表一一对应的持久化对象。
- `mapper`：MyBatis Plus BaseMapper 扩展。
- `dto`：入参校验对象；`vo`：出参对象，禁止 Entity 直接返回前端。
- `service`：业务逻辑与事务边界；`controller` 只做参数接收与响应包装。
- 所有接口统一返回 `Result<T>`；分页统一返回 `PageResult<T>`。

## 3. MySQL 初始化脚本设计

### 3.1 设计约定

- 数据库：`agentforge`，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`，引擎 InnoDB。
- 脚本位置：`docker/mysql/init/`，由 MySQL 容器首次启动时自动执行。
- 全部表增加 `deleted` 逻辑删除字段（配合 MyBatis Plus 逻辑删除），不物理删除业务数据。
- 时间字段统一 `DATETIME`，`created_time` 默认当前时间，`updated_time` 自动更新。
- 外键保留在初始化脚本中，保证数据完整性；应用层通过索引保证查询性能。
- Phase 2 起引入 Flyway 做版本化迁移，现有脚本作为初始基线迁移。

### 3.2 表结构设计

### 4.2 接口清单

| 方法 | 路径 | 说明 | 核心请求 | 核心响应 |
|---|---|---|---|---|
| GET | /health | 存活与依赖状态 | - | `{status, redis, qdrant}` |
| POST | /agent/chat | 对话执行 | `{agentId, message, history?}` | `{answer, sources[], toolCalls[]?}` |
| POST | /rag/ingest | 文档入库 | `{agentId, fileName, filePath}` | `{status, chunkCount}` |
| POST | /rag/search | 知识检索（调试/内部用） | `{agentId, query, topK}` | `{chunks[]}` |
| DELETE | /rag/file | 删除某文档的向量 | `{agentId, fileName}` | `{deletedCount}` |

### 4.3 关键设计

- **Agent Runtime**：以 LangGraph 的 `StateGraph` 实现。Phase 2 先走「LLM 直接回答」线性链路，Phase 4 演进为 planner → RAG/工具分支 → LLM → 输出的完整循环。
- **RAG**：Qdrant collection 按智能体隔离（`agent_{agentId}`）；PDF 用 pypdf/pdfplumber 解析，切分策略默认按 500 token + 50 token 重叠（后续可配置）。
- **Embedding**：通过 OpenAI 兼容接口调用，模型与维度可配置（DeepSeek/Qwen/Ollama）。
- **Memory**：Redis key `memory:agent:{agentId}`，保存最近 N 轮对话（默认 10 轮），TTL 24 小时。
- **内部鉴权**：所有接口校验请求头 `X-Internal-Token`，与后端 JWT 体系隔离。
- **Mock 模式**：未配置 LLM Key 时返回模拟回答，保证本地开发不依赖外部服务。

## 6. Docker Compose 设计

### 6.1 服务清单

| 服务 | 构建/镜像 | 端口（宿主机） | 说明 |
|---|---|---|---|
| mysql | mysql:8.0 | 3306（仅开发暴露） | 挂载 init SQL 与数据卷，healthcheck mysqladmin ping |
| redis | redis:7-alpine | 6379（仅开发暴露） | 数据卷，healthcheck redis-cli ping |
| qdrant | qdrant/qdrant | 6333（仅开发暴露） | 数据卷，healthcheck /healthz |
| ai | build ./agentforge-ai | 8000（仅内网/开发） | 环境变量注入 LLM 与内部 Token，依赖 redis/qdrant |
| backend | build ./agentforge-backend | 8080（仅内网/开发） | 多阶段 Maven 构建，依赖 mysql/redis |
| web | build ./agentforge-web | 内部 80 | 多阶段构建产物（静态 SPA） |
| nginx | nginx:1.27-alpine | 80/443 对外 | 边缘网关：/ → web，/api → backend，/ai → ai |

### 6.2 网络与卷

- 单一 bridge 网络 `agentforge-net`，容器间通过服务名通信。
- 数据卷：`agentforge-mysql-data`、`agentforge-redis-data`、`agentforge-qdrant-data`。
- 共享文件卷：`agentforge-uploads`，后端写入、AI 服务读取（RAG 解析）。

### 6.3 启动顺序与健康检查

```text
mysql ──┐
redis ──┼──► backend ──► web ──► nginx（对外入口）
        │
qdrant ─┼──► ai ──┐
        └─────────┘
```

- 使用 `depends_on` + `condition: service_healthy` 保证中间件就绪后再启动应用。
- 后端提供 `/actuator/health`，AI 提供 `/health` 作为健康检查端点。

### 6.4 环境变量管理

- 仓库提供 `.env.example`，`docker-compose.yml` 通过 `${VAR}` 引用。
- 敏感项不提交仓库：`MYSQL_ROOT_PASSWORD`、`JWT_SECRET`、`LLM_API_KEY`、`INTERNAL_TOKEN`。
- 应用内禁止硬编码：数据库、Redis、Qdrant、AI 服务地址全部走环境变量。

### 6.5 开发形态（docker-compose.dev.yml）

- 仅启动 mysql、redis、qdrant 三个中间件，端口映射到本机。
- 三端本地开发：后端直连 `localhost` 中间件；AI 服务本地起 uvicorn；前端 Vite dev server + proxy。
- 生产/演示形态：`docker compose up -d --build` 一键启动全部 7 个服务。

## 7. 服务通信方案

### 7.1 通信总览

```text
浏览器
  │ HTTPS /api/*（Bearer JWT）
  ▼
Nginx（边缘网关）
  ├── /        → web（SPA 静态资源）
  ├── /api/*   → backend:8080
  └── /ai/*    → ai:8000（内网，X-Internal-Token）

backend ──► MySQL（业务数据）、Redis（会话/缓存）
ai      ──► Redis（短期记忆）、Qdrant（向量）、LLM（HTTP，OpenAI 兼容）
```

### 7.2 协议与数据格式

- 前后端：REST + JSON，统一响应 `Result<T> { code, message, data }`，分页 `PageResult<T> { list, total, page, size }`。
- 后端 ↔ AI：REST + JSON，请求头 `X-Internal-Token`；AI 端口不对宿主机开放，仅内网可达。
- 错误码分段约定：
  - `10xxx`：参数/业务错误
  - `20xxx`：认证/授权错误
  - `30xxx`：AI 服务错误（`30001` AI 超时、`30002` AI 不可用、`30003` LLM 错误）
  - `40xxx`：文件/RAG 错误

### 7.3 同步与流式演进

- **Phase 1-2**：同步 JSON。后端调用 AI 连接超时 5s、读取超时 60s（可配置），超时返回 `30001`。
- **Phase 3+**：长回答走 SSE。后端新增 `/api/chat/stream`，透传 AI 的 `/agent/chat/stream`；前端 fetch stream 实现打字机效果。
- 重试策略：`/rag/ingest` 等幂等操作支持超时重试；chat 不自动重试（避免重复计费）。

### 7.4 文件与 RAG 链路

上传：

```text
前端 multipart → 后端校验（类型/大小 ≤20MB）→ 落盘共享卷 /data/uploads/{agentId}/{uuid}.ext
→ 写 document 行（PENDING）→ 调 AI POST /rag/ingest
→ AI 解析 → 切分 → Embedding → 写入 Qdrant（collection: agent_{agentId}）
→ 返回 chunkCount → 后端更新 status=READY/FAILED → 前端轮询/SSE 刷新状态
```

查询：

```text
用户问题 → 后端 /api/chat → AI /agent/chat
→ 问题 Embedding → Qdrant 检索 topK → 相关文本注入 Prompt
→ LLM 回答 → 返回 answer + sources（来源文件名列表）→ 后端存 conversation 并透传前端
```

删除文件：后端删除 document 元数据与磁盘文件，并调 AI `DELETE /rag/file` 删除对应 Qdrant 点。

### 7.5 记忆与缓存边界

| 存储 | 用途 | 读写方 |
|---|---|---|
| MySQL | 用户、Agent、对话历史、文档元数据 | 后端 |
| Redis | 会话缓存 `session:user:{id}`、Agent 配置缓存 `cache:agent:{id}` | 后端 |
| Redis | 短期记忆 `memory:agent:{agentId}`（最近 10 轮，TTL 24h） | AI 服务 |
| Qdrant | 向量 + payload（agentId/file/page/content） | AI 服务 |

### 7.6 安全边界

- 外部流量只经过 Nginx → 后端（JWT 校验）。
- AI 服务、MySQL、Redis、Qdrant 默认不暴露宿主机端口；开发环境按需映射。
- 内部服务间使用独立 `INTERNAL_TOKEN`，与用户 JWT 体系完全隔离。
