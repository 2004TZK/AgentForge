# 用户自定义工具开发文档（Tool Definition）

> 版本：v3.0
> 日期：2026-08-06
> 状态：**已实施（M5，2026-08-06）** —— 六阶段全部落地，AI 侧冒烟测试 + 后端集成测试通过
> 适用范围：AgentForge「用户在前端直接定义自己想用的工具，并绑定给智能体」能力
> 范围确认：**C 方案**——同时支持 HTTP API 工具与代码（脚本）工具，代码工具通过沙箱执行器运行

---

## 1. 功能概述

### 1.1 需求澄清

目标不是"用户在前端调用项目现有的内置工具"，而是：

> **用户可以在前端直接配置/创建自己想用的工具**，形成个人工具库，再选择绑定给某个智能体使用。

### 1.2 支持的两种工具形态（C 方案）

| 形态 | 用户在前端填写什么 | 执行方式 |
|------|--------------------|----------|
| HTTP API 工具 | 方法、URL 模板、请求头、query、Body、认证方式 | AI 服务按定义发起 HTTP 请求 |
| 代码（脚本）工具 | 一段 Python / JavaScript 代码 + 入参 Schema | AI 服务把代码和参数交给**沙箱执行器**运行 |

典型场景：

- HTTP 工具：查天气、查库存、调用业务系统接口；
- 代码工具：数据清洗/去重排序、文本处理、自定义计算逻辑（如"写一个函数统计 JSON 里每个字段的出现次数"）。

## 3. 目标能力与差距

| # | 目标能力 | 现状 | 差距 |
|---|----------|------|------|
| 1 | 用户自定义工具数据模型与 CRUD | 无 `tool_definition` 概念 | 需新增表 + 管理 API |
| 2 | AI 服务动态注册用户工具 | `TOOL_REGISTRY` 为静态字典 | 需支持请求级动态注册 |
| 3 | HTTP 工具执行器 | 无通用 HTTP 执行 | 需新增 executor |
| 4 | 代码工具 + 沙箱执行器 | 无 | 需新增 sandbox 服务与执行链路 |
| 5 | Agent 绑定自定义工具 | `agent_tool.tool_name` 仅指向内置注册表 | 需区分内置/自定义来源 |
| 6 | 前端工具定义编辑器（含代码编辑器） | 只有 Agent 内嵌配置表单 | 需独立工具库页面 |
| 7 | 定义可测试 | 无 | 需测试接口 + 前端按钮 |
| 8 | 安全（SSRF/密钥/沙箱/权限） | 内置工具密钥明文存储 | 需加密、脱敏、SSRF、沙箱、限流 |

## 4. 总体设计

### 4.1 数据流（HTTP 工具）

```text
用户在工具库页定义 HTTP 工具 → tool_definition 表（密钥加密）
        → Agent 编辑页绑定 → 聊天时后端装配 customTools 透传
        → AI 服务动态注册 → LLM 决策调用 → http_tool 执行器发请求 → 结果回填
```

### 4.2 数据流（代码工具）

```text
用户在工具库页编写代码 → tool_definition 表（tool_type=script）
        → Agent 编辑页绑定 → 聊天时后端装配 customTools 透传
        → AI 服务动态注册 → LLM 决策调用
        → script executor 将 {代码, 参数} POST 给 sandbox 服务
        → sandbox 受限执行 → 返回 stdout/结果/错误 → 结果回填 LLM
```

### 4.3 分层职责

| 层 | 职责 |
|----|------|
| 前端 | 工具库管理页（HTTP 表单 + 代码编辑器）+ Agent 绑定选择器 + 测试按钮 |
| Java 后端 | `tool_definition` CRUD（创建者隔离）；Agent 绑定校验；聊天装配 `customTools` |
| AI 服务 | 动态注册自定义工具；HTTP executor；script executor（对接沙箱）；Schema 生成 |
| sandbox 服务 | 受限执行用户代码：超时/内存/CPU/输出上限、无外网、非 root、只读文件系统 |

## 5. 数据模型

### 5.1 新增 `tool_definition` 表

```sql
CREATE TABLE IF NOT EXISTS `tool_definition` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `creator_id`     BIGINT UNSIGNED NOT NULL COMMENT '创建者ID',
  `name`           VARCHAR(100)    NOT NULL COMMENT '工具名（用户级唯一，供 LLM 调用）',
  `display_name`   VARCHAR(100)    NOT NULL COMMENT '展示名称',
  `description`    VARCHAR(500)    DEFAULT NULL COMMENT '给 LLM 看的工具描述',
  `tool_type`      VARCHAR(20)     NOT NULL COMMENT 'http / script',
  `parameters`     JSON            NOT NULL COMMENT 'LLM 调用参数 Schema（OpenAI function parameters）',
  `http_config`    JSON            DEFAULT NULL COMMENT 'HTTP 请求定义（tool_type=http）',
  `script_config`  JSON            DEFAULT NULL COMMENT '代码定义（tool_type=script）',
  `visibility`     VARCHAR(20)     NOT NULL DEFAULT 'PRIVATE' COMMENT 'PRIVATE/PUBLIC',
  `deleted`        TINYINT(1)      NOT NULL DEFAULT 0,
  `created_time`   DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_time`   DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_creator_name` (`creator_id`, `name`),
  KEY `idx_creator` (`creator_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='用户自定义工具定义';
```

`http_config` 示例：

```json
{
  "method": "POST",
  "url": "https://api.example.com/v1/weather",
  "headers": { "Content-Type": "application/json" },
  "bodyTemplate": { "city": "{city}", "lang": "zh" },
  "query": { "key": "{api_key}" },
  "auth": { "type": "api_key", "headerName": "X-API-Key", "value": "{api_key}" },
  "timeoutSeconds": 15
}
```

`script_config` 示例：

```json
{
  "language": "python",
  "source": "def run(args):\n    items = args.get('items', [])\n    return sorted(set(items))",
  "entrypoint": "run"
}
```

### 5.2 代码工具执行约定

- **Python**：定义 `def run(args: dict)`，返回可 JSON 序列化的值（dict / list / str / number / bool）；
- **JavaScript**：定义 `export function run(args)`，返回同样可 JSON 序列化的值；
- `args` 由 LLM 依据 `parameters` Schema 填充；执行结果统一序列化为字符串回填 LLM。

### 5.3 扩展 `agent_tool` 表

```sql
ALTER TABLE `agent_tool`
  ADD COLUMN `tool_source`        VARCHAR(16)  NOT NULL DEFAULT 'builtin' COMMENT 'builtin/custom',
  ADD COLUMN `tool_definition_id` BIGINT UNSIGNED DEFAULT NULL COMMENT '自定义工具定义ID';
```

## 6. 沙箱执行器设计（C 方案核心）

### 6.1 架构

新增独立容器服务 `sandbox`，**`network_mode: none`（容器本身无外网）**，仅 AI 服务可通过内部 HTTP 调用：

```text
AI 服务（script executor）
   │  POST /run  {language, source, args, limits}
   ▼
sandbox 容器（network_mode: none）
   │ 受限子进程执行用户代码
   ▼
返回 {ok, result | error, stdout, durationMs}
```

### 6.2 资源与执行约束（默认值）

| 约束 | 默认值 | 说明 |
|------|--------|------|
| 超时 | 10s（可配置 1–60s） | 超时强杀进程，错误回填 LLM |
| 内存 | 256MB | 超限直接终止 |
| CPU | 1 核 | 防止占满宿主 |
| 输出上限 | 1MB | stdout / 返回值截断 |
| 代码大小 | ≤ 50KB | 前端与后端双重校验 |
| 文件系统 | 只读 + 独立临时目录 | 不可读写宿主文件 |
| 运行用户 | 非 root（nobody） | 降权执行 |
| 并发/限流 | 每用户并发上限 + 服务级 QPS | 防资源耗尽 |

### 6.3 隔离层次与安全边界（重要）

- **MVP 定位为"受限执行"**：非 root + 无外网 + 资源限制 + 只读文件系统，能挡住绝大多数误用与常见攻击，但**不是对抗性多租户强隔离**（不承诺能防住恶意用户精心构造的内核漏洞利用）；
- 如后续需要强隔离（多租户、不可信用户），升级路线：**每次调用启动一次性 Docker 容器 + seccomp + 文件系统快照**，再进阶 gVisor / Firecracker，均后置；
- **默认无外网**：代码工具不能访问网络（与 HTTP 工具不同）。若需要联网代码工具，后续提供受控代理白名单，不在本阶段范围；
- 禁用危险模块/能力（如 `os.system`、`subprocess`、socket 由无外网天然阻断；Python 可叠加 `RestrictedPython` 语法白名单，作为加固项）。

### 6.4 sandbox 服务接口

```text
POST /run
{
  "language": "python" | "javascript",
  "source": "…",
  "args": { … },
  "limits": { "timeoutSeconds": 10, "memoryMb": 256 }
}
→ 200
{
  "ok": true,
  "result": { … },          // JSON 可序列化结果
  "stdout": "…",             // 截断后的输出
  "durationMs": 123
}
→ 200（执行失败/被限制）
{
  "ok": false,
  "error": "TimeoutError | MemoryLimitError | SyntaxError | …"
}
```

## 7. 实施方案

### 阶段一：后端数据模型 + 管理 API（Java）

- 新增 `tool_definition` 实体/Mapper/Service/Controller（`/tool-definitions`）：
  - CRUD，创建者隔离（PRIVATE 仅创建者可见，PUBLIC 所有人可见但密钥脱敏）；
  - 校验：`name` 正则（`^[a-z][a-z0-9_]{1,49}$`）、用户级唯一、**不得与内置注册表工具重名**；
  - `parameters` 必须为合法 JSON Schema；`tool_type` 为 http/script 时分别校验 `http_config` / `script_config`（必填字段、代码大小 ≤ 50KB）；
  - 密钥字段 AES-GCM 加密入库，详情返回脱敏为 `********`；
- 新增迁移脚本 `docker/mysql/upgrade/20260806-add-tool-definition.sql`（含 `agent_tool` 扩展列）；
- `AgentService` 保存工具时校验：`tool_source=builtin` 查注册表；`tool_source=custom` 校验 `tool_definition` 存在且有权限。

### 阶段二：HTTP 工具执行器（Python）

- `registry.py` 新增动态注册能力：`register_custom_tool(name, schema, handler)`、`openai_tools(tool_names, custom_tools)`；
- 新增 `app/tools/http_tool.py`：
  - URL 模板渲染（`{param}`）、query/headers/body 模板、认证注入（api_key / bearer / basic）；
  - httpx 统一超时、响应体上限（1MB）、非 2xx 转失败文本；
  - **SSRF 防护**：默认拒绝内网/保留地址段，DNS 解析后二次校验，可配置开关；
- `ChatRequest` 新增 `customTools: List[Dict]`，`agent_runtime` 每次请求开始时注册、结束后注销。

### 阶段三：代码工具 + 沙箱执行器（Python + 新服务）

- 新增 `docker/sandbox/Dockerfile` 与 compose 服务 `sandbox`（`network_mode: none`，内部网络可达 AI 服务）；实现 `POST /run`：
  - Python：`subprocess` 受限执行 + `resource` 限制（内存/CPU）+ 超时强杀 + 非 root + 只读根；
  - JavaScript：优先 Node.js 子进程 + 相同资源约束；后续可换更严的受限运行时；
  - 统一输出截断与错误分类（Timeout / Memory / Syntax / Runtime）；
- AI 服务新增 `app/tools/script_tool.py`（script executor）：校验来源为定义内的代码 → 组装 `/run` 请求 → 解析结果/错误回填；
- sandbox 服务加鉴权（内部 Token）与限流。

### 阶段四：Agent 绑定 + 装配链路

- `agent_tool` 增加 `tool_source` / `tool_definition_id`；`AgentDetailVO` / `ToolConfigRequest` 同步扩展；
- `ConversationServiceImpl` 装配 `AiChatRequest`：`tools`（内置 + 自定义名）、`toolConfigs`（Agent 级密钥覆盖，解密后）、`customTools`（定义：schema + http_config/script_config，解密后）；
- 前端 AgentEdit TOOLS 区块增加来源选择：内置工具 / 我的自定义工具。

### 阶段五：前端工具库页面（Vue）

新增路由 `/tools`、`/tools/new`、`/tools/:id/edit`：

- **工具库列表**：我的工具 / 公开工具，支持复制、删除（仅创建者）；
- **HTTP 工具编辑器**：基本信息、参数 Schema 行式编辑、请求定义（method/URL 模板/headers/query/Body）、认证配置（密钥密码框 + 脱敏回显）、测试按钮；
- **代码工具编辑器**：语言选择（Python / JavaScript）、代码输入区（等宽文本域起步，后续可接 Monaco）、入参 Schema 行式编辑、**示例参数 + 测试按钮**（调沙箱真实执行一次）；
- AgentEdit 自定义工具卡片：定义摘要 + 该 Agent 的密钥/参数覆盖 + 测试按钮。

### 阶段六：安全收口

- 密钥：`http_config` / `script_config` / `agent_tool.tool_config` 中 secret 字段统一 AES-GCM 加密、详情脱敏、编辑留空不修改；
- SSRF：IP 段校验 + DNS 二次校验 + 超时与响应大小限制；
- 沙箱：超时/内存/CPU/输出/代码大小/并发限流（见 6.2）；
- 权限：PRIVATE 仅创建者可绑定/测试；PUBLIC 可被他人绑定但看不到密钥明文；
- 审计（可选）：记录工具定义变更与沙箱执行失败事件。

## 8. 验收标准

### HTTP 工具

- 用户能在前端创建 HTTP 工具并保存到个人工具库；
- 该工具能出现在 Agent 编辑页可选列表，绑定后保存成功；
- 聊天中 LLM 依据用户填写的 parameters 自主调用，并基于结果回答；
- 未配置密钥/密钥错误时返回可读失败信息，不阻断主链路；
- 内网/保留 IP 段请求被拦截，超时与超大响应被截断。

### 代码工具

- 用户能在前端编写 Python/JS 工具并保存；
- 聊天中 LLM 调用时，代码在 sandbox 内执行，结果回填回答；
- 超时、内存超限、语法错误、运行时异常均返回可读错误且不阻断主链路；
- 代码无法访问外网、无法读写宿主文件系统、非 root 执行；
- 超过代码大小/并发上限的请求被拒绝。

### 通用

- 密钥明文不出现在任何前端接口响应中，数据库为密文；
- 每个工具定义页与 Agent 绑定卡片均有"测试"按钮且结果可读。

## 9. 实施顺序与工作量

| 阶段 | 内容 | 工作量 | 依赖 |
|------|------|--------|------|
| 一 | 后端 `tool_definition` CRUD + 迁移 + Agent 绑定校验 | 1 ~ 2 天 | 无 |
| 二 | HTTP 工具动态注册 + executor + SSRF 防护 | 1 ~ 2 天 | 一 |
| 三 | 代码工具 + sandbox 服务 | 2 ~ 3 天 | 一 |
| 四 | Agent 绑定 + 聊天装配透传 | 0.5 ~ 1 天 | 二、三 |
| 五 | 前端工具库页面 + 测试按钮 | 2 ~ 3 天 | 一、二、三 |
| 六 | 安全收口（密钥/SSRF/沙箱/限流/审计） | 1 ~ 2 天 | 贯穿 |

**建议顺序**：阶段一 → 二（HTTP 打通"定义→执行"）→ 三（沙箱）→ 四（Agent 接入）→ 五（前端体验）→ 六（安全收口）。
