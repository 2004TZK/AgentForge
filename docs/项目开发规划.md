## 2. 决策记录（已确认，不再返工）

| # | 决策项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 模型选型（Embedding + 对话） | **Ollama 本地双模型：bge-m3（向量）+ qwen3.5:0.8b（对话，默认 `LLM_THINK=false`），不使用 DeepSeek（云端 API 与本地 r1 均不用）** | 全部本地免费、可离线演示、无 Token 费用；本机无独显（CPU 推理、15.2GB 内存），7B 虚拟内存占用过高，0.8B 可稳定运行；bge-m3 多语言检索维度 **1024**；qwen3.5 支持工具调用。代码层保留 OpenAI 兼容抽象，未来可随时切回云端服务 |
| 2 | 多会话 | **做基础版**：新增 `session` 表 + 会话列表/新建/切换/删除，放 M2 | 体验刚需；RAG 上线前定结构避免返工；不做重命名/搜索/分享/归档 |
| 3 | SSE 流式时机 | **提前至 M1** | 打字机效果是演示体验差异最大的功能；独立闭环 2 天内完成，先踩长连接/超时/中断的坑，后续 RAG 与工具循环直接复用 |
| 4 | Workflow 形态 | **轻量 YAML/JSON 流程定义 + LangGraph 编译执行**；可视化拖拽明确不做 | 流程引擎才是技术含量所在；拖拽编辑器是产品级工作量，单人项目必然拖垮工期。后续可补"只读流程图谱"提升观感 |
| 5 | 开源协议 | **MIT** | 最宽松、零合规负担，适合原创个人开源项目；Apache-2.0 的专利/NOTICE 要求对求职展示项目无收益 |
| 6 | 权限增强 | **仅做公开/私有可见性**（`visibility` 字段 + 查询过滤），成员协作砍掉 | 1-2 天提升多用户演示可信度；成员/角色/ACL 后置 v1.1+ |
| 7 | Ollama 模型目录 | 宿主机 bind mount（`D:/ollama`），不存容器层 | 升级容器不重复拉取、模型与容器解耦、节省磁盘 |
| 8 | 本地模型调用协议 | **Ollama 原生 `/api/chat`（think 可控）**；远端模型仍走 OpenAI 兼容 | OpenAI 兼容 `/v1/chat/completions` 不识别 `think` 参数，qwen3.5 会持续输出思考 token 导致响应极慢；原生接口支持 `think=false`，聊天响应提速 10 倍以上 |
| 9 | 落地目标 | **第一种：M3+M4 完成即发布 v1.0.0 开源版本（能跑能演示 + 规范开源）；不做生产级**（高并发、安全合规、高可用、运营配套全部后置） | 面向 2027 求职的个人开源项目，开源 v1.0 已具备完整展示价值（可现场演示、可 clone 复现）；生产级投入产出比低，避免拖垮工期 |

## 5. M3：Phase 4 Agent 能力增强 ✅ 已完成

### 交付内容

- LLM 工具决策：规则触发升级为 LLM 依据工具 Schema 自主选择（OpenAI 兼容 `tools` 参数与 `think` 并存，Ollama 原生 `/api/chat`；qwen3.5 真实调用验证通过）
- 多轮工具循环：LangGraph ReAct 图（call_llm → 路由 → execute_tool 回填 → 总结，上限 3 轮），SSE 新增 `tool` 事件实时展示工具活动；规则触发（关键字启发式）保留为兜底：LLM 未决策工具时按规则执行并回填重新总结；工具失败转为失败文本回填，不阻断主链路
- 工具 Schema 化：注册表补齐 OpenAI function 格式（type=function）与 config 元数据；新增 `GET /tools/meta` 代理；前端 AgentEdit 按 Schema 渲染工具配置表单（动态选项 + config 字段，api_key 用密码框）
- 工具扩展：新增 `current_time`（离线）与 `web_search`（占位，支持 tool_config.api_key 配置）；github 支持配置 API Token 提升限流
- Memory 接线：key 修正为 `memory:agent:{agentId}:user:{userId}`（后端 chat 请求透传 userId）；对话后写入最近 10 轮（TTL 24h）；与 MySQL 历史去重后注入系统提示词（跨会话/设备回忆）；Redis 不可用自动降级
- Workflow v1：`workflow` + `workflow_node` + `workflow_run` 三表（迁移 `docker/mysql/upgrade/20260803-add-workflow.sql`）；定义 CRUD（创建者隔离）+ 触发运行 + 节点级日志；AI 服务 LangGraph 编译线性链执行（模板变量 `{var}`、节点类型限定 tool/llm、失败标记 FAILED）；Agent 新增运行模式（chat/workflow，绑定本人工作流校验），对话消息作为 `{message}` 触发流程，答案取输出（同步与 SSE 双路径）；前端工作流列表/编辑页（节点编辑器 + 只读图谱 + 运行测试 + 节点日志）

### 验收结果

- Agent 自主决定调用工具并基于结果继续回答；工具失败不影响主链路 ✅
- 不同用户使用同一 Agent 互不串记忆（Redis key 按用户隔离验证） ✅
- 简单工作流（查仓库 → 算指标 → 生成报告）可定义并执行，节点日志可查 ✅
- Python 61/61 通过（ReAct/兜底/记忆隔离/Schema/引擎）；Java 26/26 通过（workflow CRUD/权限/运行/Agent 触发）
- 真实 Ollama 模型全栈 E2E 通过（工具决策 + 流式 tool 事件 + 两用户记忆隔离 + 工作流三节点执行）

## 6. M4：Phase 5 工程化与开源发布 ✅ 已完成

### 交付内容

- **CI/CD**：GitHub Actions 三端验证（backend `mvn test` / ai `pytest` / web `npm test` + `npm run build`），main 推送时 buildx 构建三镜像发布 GHCR（含构建缓存）
- **测试补全**：Java 43 个集成测试（新增 Chat 流式落库/越权、File CRUD/权限、Provider CRUD/归属）；Python 64 个单测（新增 Provider 覆盖）；前端 vitest + jsdom 冒烟 4 用例
- **部署加固**：HTTPS 自动化（ssl-init 容器生成自签证书，幂等，nginx 443 双通道）；全局日志 json-file 10m×3 轮转；各服务内存资源上限；`scripts/backup.sh`（MySQL 全量 + Qdrant 官方快照，保留 7 天）+ `scripts/restore.md`
- **多模型配置**：`model_provider` 表 + 管理页（多 Provider 并存：本地 Ollama 原生 / OpenAI 兼容远端）；Agent 绑定 providerId；AI 服务请求级 Provider 覆盖（base_url/api_key 透传），未绑定回落内置 Ollama
- **公开/私有可见性**：`visibility` 字段（默认 PRIVATE）；列表过滤、详情/聊天视为不存在（10003）、内置 Provider 不可改删；前端列表徽标 + 编辑单选
- **开源规范**：MIT LICENSE、CONTRIBUTING、CODE_OF_CONDUCT、Issue/PR 模板、CHANGELOG
- **项目宣传**：README 重写（架构图、功能表、真实运行截图 4 张——含工具调用对话与工作流编辑）
- **前端代码分割**：Element Plus 按需引入 + manualChunks 分包，主包 1040KB→9KB、CSS 360KB→52KB，消除 >500KB 警告
- **数据库迁移自动化**：`migrate` 一次性容器 + `schema_migrations` 幂等记录，替代手动 `mysql <` 升级；历史脚本全部幂等化

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Ollama 模型拉取网络问题 | RAG 无法落地 | compose 内预拉模型；失败换镜像源或临时换 nomic-embed-text（配置级切换） |
| bge-m3 维度与 Qdrant 集合不一致 | 检索报错 | 维度常量集中配置 + 集合重建脚本（已固化 1024，M2 已验证） |
| 0.8B 模型回答质量有限（偶尔答非所问） | 演示效果打折 | 联调可接受；正式演示前按内存余量升级 qwen2.5:1.5b/3b（仅改 `.env` 配置） |
| CPU 推理慢（长 RAG 上下文 25-115s） | 等待感强 | `LLM_THINK=false` 已默认；SSE 流式缓解感知；可裁剪 RAG 检索条数/上下文长度 |
| 7B 模型虚拟内存占用过高 | 本机卡顿 | 已换 0.8B；模型目录绑定宿主机 `D:/ollama`，模型与容器解耦 |
| LLM 工具调用不稳定 | 工具循环体验差 | 保留规则触发兜底；工具 Schema 严格校验 |
| Workflow 复杂度膨胀 | 工期失控 | 轻量 YAML 流程限定节点类型；可视化明确后置 |
| 时间冲突（求职季） | 进度拖延 | 里程碑可裁剪：Tool 循环与 Memory 优先，Workflow 可后置 |
| 密钥/数据安全 | 泄露风险 | `.env` 隔离；CI 密钥用 Secrets；演示数据脱敏 |
