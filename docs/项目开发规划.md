## 2. 决策记录（已确认，不再返工）

| # | 决策项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 模型选型（Embedding + 对话） | **Ollama 本地双模型：bge-m3（向量）+ qwen2.5:7b（对话），不使用 DeepSeek（云端 API 与本地 r1 均不用）** | 全部本地免费、可离线演示、无 Token 费用；bge-m3 多语言检索，维度 **1024** 需同步 `EMBEDDING_DIM` 与 Qdrant 集合；qwen2.5 工具调用支持稳定。代码层 OpenAI 兼容抽象保留，未来可随时切回云端服务 |
| 2 | 多会话 | **做基础版**：新增 `session` 表 + 会话列表/新建/切换/删除，放 M2 | 体验刚需；RAG 上线前定结构避免返工；不做重命名/搜索/分享/归档 |
| 3 | SSE 流式时机 | **提前至 M1** | 打字机效果是演示体验差异最大的功能；独立闭环 2 天内完成，先踩长连接/超时/中断的坑，后续 RAG 与工具循环直接复用 |
| 4 | Workflow 形态 | **轻量 YAML/JSON 流程定义 + LangGraph 编译执行**；可视化拖拽明确不做 | 流程引擎才是技术含量所在；拖拽编辑器是产品级工作量，单人项目必然拖垮工期。后续可补"只读流程图谱"提升观感 |
| 5 | 开源协议 | **MIT** | 最宽松、零合规负担，适合原创个人开源项目；Apache-2.0 的专利/NOTICE 要求对求职展示项目无收益 |
| 6 | 权限增强 | **仅做公开/私有可见性**（`visibility` 字段 + 查询过滤），成员协作砍掉 | 1-2 天提升多用户演示可信度；成员/角色/ACL 后置 v1.1+ |

## 3. M1：Phase 2 收尾（稳定性、体验与流式输出）

### 目标

把已打通的 AI 链路打磨到"可稳定、流式、有反馈"地演示。

### 任务分解

| 任务 | 说明 | 预估 | 能力标签 |
|---|---|---|---|
| AI 错误响应规范化 | LLM 失败返回结构化错误（区分 30002 服务不可用 / 30003 模型错误）；后端 ai-gateway 映射细化 | 0.5d | 后端 |
| **SSE 流式输出** | AI 服务 `/agent/chat/stream`（SSE）→ 后端 `/api/chat/stream` 透传 → 前端 fetch stream 打字机渲染；处理断开/超时 | 2d | 后端+前端 |
| 前端聊天体验 | 发送失败重试、错误提示、思考中状态优化、消息失败标记 | 1d | 前端 |
| Java 测试基础 | 注册/登录/401 拦截/Agent CRUD 集成测试（H2 或 Testcontainers） | 1.5d | 后端 |
| 文档同步 | `docs/api.md` 补齐 chat/chat-stream 接口与错误码 | 0.5d | 工程 |

### 验收标准

- 聊天回答以打字机效果流式呈现，断开连接可恢复提示
- Ollama 未启动 / 模型未拉取 / 超时三种场景均有可读提示，后端日志可定位
- `mvn test` 通过，核心接口有测试覆盖

## 4. M2：Phase 3 RAG 知识库 + 多会话

### 目标

让 Agent "读过文档再回答"，并支持多会话管理。

### 前置（本阶段第一天完成）

- `docker-compose.yml` 增加 `ollama` 服务（第 8 个容器），拉取两个模型：`bge-m3`（向量）+ `qwen2.5:7b`（对话）
- AI 服务配置：`EMBEDDING_BASE_URL=http://ollama:11434/v1`、`EMBEDDING_MODEL=bge-m3`、`EMBEDDING_DIM=1024`；对话配置 `LLM_BASE_URL=http://ollama:11434/v1`、`LLM_MODEL=qwen2.5:7b`（本地模型无需 API Key）
- Qdrant 集合按 1024 维度重建；`.env` 中原 DeepSeek Key 清除，避免误用
- 若 Ollama 模型拉取失败：重试或换国内镜像源；Embedding 兜底可临时换 `nomic-embed-text`（仅改配置）

### 任务分解

| 任务 | 说明 | 预估 | 能力标签 |
|---|---|---|---|
| Embedding 接入 | OpenAI 兼容 `/embeddings`；替换哈希 Mock 向量；维度一致性校验 | 1d | AI |
| 切分策略参数化 | chunk 大小/重叠可配；长文档分页信息保留 | 1d | AI |
| 检索增强 QA | 问答检索 topK → 注入 Prompt → 回答；空知识库自动降级普通对话 | 1.5d | AI |
| 来源引用 UI | 回答展示引用文件列表（可查看片段） | 1d | 前端 |
| 文档管理完善 | 重试/删除状态机；同名文件覆盖策略；集合一致性 | 1d | 后端 |
| **多会话** | `session` 表 + 会话 CRUD API + 前端会话列表/切换；conversation 表增加 `session_id` 迁移 | 2d | 后端+前端 |
| RAG 质量验证 | 构造测试语料，验证检索准确率与引用正确性 | 1d | 工程 |

### 验收标准

- 上传 PDF/Word/文本后，问答引用对应片段且来源正确；未上传知识库的 Agent 自动降级
- 同一 Agent 可创建/切换多个会话，历史互不混淆
- Qdrant 数据随文档删除/重传保持一致

## 5. M3：Phase 4 Agent 能力增强

### 目标

从"单轮问答"进化为"会规划、会用工具、有记忆、能跑流程"的 Agent。

### 5.1 Tool Calling 升级

| 任务 | 说明 | 预估 | 能力标签 |
|---|---|---|---|
| LLM 工具决策 | 规则触发升级为 LLM 依据工具 Schema 自主选择（OpenAI 兼容 `tools` 参数）；qwen2.5 原生支持工具调用，可直接对接 | 2d | AI |
| 多轮工具循环 | LangGraph 实现 planner → 工具执行 → 结果回填 → LLM 总结（ReAct）；保留规则触发兜底 | 2d | AI |
| 工具 Schema 化 | 注册表补齐 JSON Schema，前端按 Schema 渲染配置表单 | 1.5d | AI+前端 |
| 工具扩展 | 新增 1-2 个工具（如 Web 搜索占位/时间天气），验证可扩展性 | 1d | AI |

### 5.2 Memory 接线

- key 修正为 `memory:agent:{agentId}:user:{userId}`（后端 chat 请求透传 userId），避免多用户串上下文
- 对话后写入最近 N 轮（TTL 24h）；MySQL 历史兜底与跨设备恢复；Redis 不可用自动降级
- 预估 1.5d，能力标签：AI + 后端

### 5.3 Workflow v1（轻量版）

| 任务 | 说明 | 预估 | 能力标签 |
|---|---|---|---|
| 流程定义模型 | `workflow` + `workflow_node` 表、CRUD 接口（YAML/JSON 定义） | 1.5d | 后端 |
| 执行引擎 | 流程定义 → LangGraph 编译执行，节点级日志 | 2d | AI |
| Agent 绑定 | Agent 可选"对话模式 / 工作流模式" | 1d | 后端+前端 |
| （可选）只读可视化 | 前端把流程定义渲染为节点图（不做交互编辑） | 1d | 前端 |

### 验收标准

- Agent 自主决定调用工具并基于结果继续回答；工具失败不影响主链路
- 不同用户使用同一 Agent 互不串记忆
- 简单工作流（如"查仓库 → 算指标 → 生成报告"）可定义并执行，节点日志可查

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Ollama 模型拉取网络问题 | RAG 无法落地 | compose 内预拉模型；失败换镜像源或临时换 nomic-embed-text（配置级切换） |
| bge-m3 维度与 Qdrant 集合不一致 | 检索报错 | 维度常量集中配置 + 集合重建脚本，M2 首日完成 |
| SSE 长连接不稳定 | 流式体验差 | M1 专门处理超时/重连/断开提示，验证后再扩展 |
| 多会话表迁移 | 历史数据兼容 | M2 提供一次性迁移脚本，保留旧数据 |
| LLM 工具调用不稳定 | 工具循环体验差 | 保留规则触发兜底；工具 Schema 严格校验 |
| Workflow 复杂度膨胀 | 工期失控 | 轻量 YAML 流程限定节点类型；可视化明确后置 |
| 时间冲突（求职季） | 进度拖延 | 里程碑可裁剪：RAG 与 Tool 循环优先，Workflow 可后置 |
| 密钥/数据安全 | 泄露风险 | `.env` 隔离；CI 密钥用 Secrets；演示数据脱敏 |
